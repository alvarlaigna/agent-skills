## Folders and naming

- Everything the game ships lives under one root, `/Game/<Project>/`. Template, sample and
  marketplace content is copied in deliberately or left out of the cook.
- Prefixes: `BP_` Blueprint, `WBP_` widget, `M_` material, `MI_` instance, `MF_` function,
  `T_` texture, `SM_` static mesh, `SK_` skeletal mesh, `ABP_` anim Blueprint, `S_`/`SW_` sound,
  `DT_` DataTable, `DA_` data asset, `NS_` Niagara system, `L_` level.
- Source files (PNG, WAV, FBX, CSV, Blender files) live in the repo outside `Content/`, for
  example `SourceArt/` or `docs/assets/`, so they can be re-imported and audited.

## Importing with Python

The editor's importer runs headless and in batches; an agent should not depend on drag and drop.

```python
import unreal

def import_files(files, dest="/Game/MyGame/Audio"):
    tasks = []
    for f in files:
        t = unreal.AssetImportTask()
        t.filename = f              # absolute path
        t.destination_path = dest
        t.automated = True          # no dialogs
        t.replace_existing = True
        t.save = True
        tasks.append(t)
    unreal.AssetToolsHelpers.get_asset_tools().import_asset_tasks(tasks)
    return [p for t in tasks for p in t.imported_object_paths]
```

- Give every tool absolute paths. Relative paths resolve against the engine's working directory,
  not the project, and fail in confusing ways.
- After import, set and verify the properties the game depends on (looping, compression, sRGB,
  collision, Nanite) and save. Check the imported asset, not the script.
- Run `scripts/audit_source_assets.py` on the source folder first.

## Textures

- Power-of-two sizes (512, 1024, 2048) for anything mipmapped or streamed. Non-power-of-two
  textures get no mips and shimmer at a distance. Fix the source, or set the import to pad or
  stretch to a power of two.
- `sRGB` off for masks, normal maps and data textures. `TC_Normalmap` for normals,
  `TC_Masks` for packed masks, `TC_UserInterface2D` for UI.
- Set `LODGroup` (UI, World, Character) so streaming and size budgets apply.
- UI and card art read at a fixed size: author at that size, power of two, and keep the text on
  them large enough for 1080p.

## Audio

- 16-bit PCM WAV, 44.1 or 48 kHz. Mono for 3D sounds, effects and most music loops in a jam:
  half the size, no stereo-field surprises when spatialized.
- Set `looping` on the imported asset for loops; the source file alone does not make it loop.
- Cut loops at zero crossings with matching slope, or they click every pass. Cut music on a bar
  line (measure the tempo).
- Normalize. Ambience generated by AI tools often lands near -40 dB and needs gain; nothing should
  clip. `scripts/audit_source_assets.py` reports peaks, clipping, silence and seam jumps.
- Agents cannot hear. Ask a human to listen to a two-minute PIE pass before any release build.
- In a browser build, audio starts muted until the first click or key press. Start music on the
  first menu interaction, or confirm it becomes audible after that click.

## Meshes

- Check the source units. A model a few centimetres long after import was authored in metres or
  another unit; scale on import or in the converter, and record the real size it should have.
- Converters that mirror an axis must reverse triangle winding too, or the mesh renders inside out.
- AI-generated meshes need checking where function depends on shape (doubled turrets, splayed
  barrels, holes in collision hulls). Cut and replace parts by script rather than by hand.
- Nanite for dense static meshes. Note what does not work with Nanite in the target renderer
  (overlay materials; the mobile renderer used by web builds).
- Collision: verify with traces, not by looking. A prop with no collision or a hull with a hole
  fails silently.

## DataTables from CSV

- Keep the CSV in the repo as the source. Re-import with the editor's DataTable import (MCP tool
  or Python), never edit rows in the editor.
- The row struct is C++ (`USTRUCT(BlueprintType) : public FTableRowBase`). Changing it needs a
  restart and a re-import.

## Moves, renames, redirectors

- Moving or renaming leaves redirectors. Fix them up (Content Browser "Fix Up Redirectors", or the
  asset tools' fix-up call in Python) before packaging.
- A renamed import can leave meshes and materials pointing at the deleted original names on disk
  while the editor shows the new ones from memory. The packaged build then shows untextured
  meshes. Package early and look at the result.
- Primary asset labels and other primary assets need unique IDs. Copying a folder that contains a
  label duplicates its ID and breaks the cook; delete helper labels after a copy.

## Cook rules and the dependency closure

In `Config/DefaultGame.ini`:

```ini
[/Script/UnrealEd.ProjectPackagingSettings]
+MapsToCook=(FilePath="/Game/MyGame/Maps/L_Main")
+MapsToCook=(FilePath="/Game/MyGame/Maps/L_Menu")
+DirectoriesToNeverCook=(Path="/Game/StarterContent")
+DirectoriesToAlwaysCook=(Path="/Game/MyGame/Data")
```

- List every shipping map. Without a list, the cook includes every map it finds, template samples
  included.
- Assets loaded only by path at runtime (strings, soft references nobody holds) are invisible to
  the cook. Reference them from a cooked asset, a primary asset rule, or `DirectoriesToAlwaysCook`.
- Before calling content done, run `scripts/editor/dependency_closure.py` for each shipping map:
  nothing outside `/Game/<Project>/` (and `/Engine/`, `/Script/`) should appear unless it is meant to.
- For a large third-party pack, cook only the folders the game uses, and track only the files the
  build actually used.

## Levels, external actors, teams

- One File Per Actor (default with World Partition) stores each actor as its own file under
  `Content/__ExternalActors__/`. Good for merges, but a script move that does not dirty the actor
  package is never saved (see [the editor loop](editor-loop.md#save-and-verify)).
- One person or agent edits a given level at a time. Pull and reopen the level before editing it.
  Concurrent edits lose actors.
- Binary assets do not merge. Use Git LFS with locking, or strict path ownership.
- A pull while the editor holds an asset open can leave the old version on disk. Restore it from
  `HEAD` after the editor closes rather than committing it.

## Generated content and provenance

- Generators belong in the repo: Blender scripts, mesh builders, texture scripts, audio
  synthesis, level layout scripts. Content can then be rebuilt and audited.
- Keep a provenance list: every third-party asset with its licence, every AI tool with what it
  made. Jams and stores ask for it.
- Read each asset's licence for AI terms. Where a pack is marked as not for AI use, agents may
  place and reference it from code but must not open, edit, copy or generate from it.
